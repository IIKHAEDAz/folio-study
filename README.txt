Folio — เปิดล็อกอินอีเมลและซิงก์

เชื่อม Project URL และ Publishable key ของโปรเจกต์ Folio แล้ว ตรวจการเชื่อมต่อระบบบัญชีและการปิดสิทธิ์ผู้ไม่ได้ล็อกอินผ่านแล้ว
ผู้ใช้รัน setup.sql สำเร็จแล้ว ต้องตั้ง Site URL ใน Dashboard ก่อนทดสอบลิงก์เข้าสู่ระบบจริง

1. สร้างโปรเจกต์ของคุณที่ https://supabase.com/dashboard
2. เปิด SQL Editor แล้ววางเนื้อหาจาก setup.sql และกด Run
   ตาราง folio_workspaces ใช้ Row Level Security ให้ผู้ใช้เข้าถึงเฉพาะข้อมูลของตนเอง
3. ใช้เทมเพลต Magic Link เริ่มต้นได้ ไม่ต้องแก้เทมเพลตเป็นรหัส OTP
4. เปิด Authentication > URL Configuration ตั้ง Site URL เป็น https://foliostudy.vercel.app แล้ว Save changes
   หากใช้โดเมนอื่นด้วย ให้เพิ่ม URL ของโดเมนนั้นใน Redirect URLs
   ขออีเมลใหม่จากหน้าเข้าสู่ระบบ แล้วแตะ Sign in ในอีเมลบนอุปกรณ์ที่ต้องการใช้งาน
   ลิงก์เก่าที่พาไป localhost ต้องขอใหม่หลังบันทึก Site URL
5. การส่งอีเมลให้คนทั่วไปต้องตั้ง Custom SMTP ด้วยบริการอีเมลของคุณ
   ระบบอีเมลเริ่มต้นของ Supabase จำกัดผู้รับเฉพาะสมาชิกทีม จึงใช้ทดสอบกับอีเมลอื่นไม่ได้
6. จากหน้า Connect / API Keys คัดลอก Project URL และ Publishable key
   หากใช้โปรเจกต์เก่า ใช้ anon key ได้ ห้ามใช้ service_role, Secret key หรือรหัสผ่านฐานข้อมูล
7. ใน index.html ค้นหา window.FOLIO_CLOUD_CONFIG แล้วกรอกค่าใน url และ publishableKey
   ตัวอย่าง: window.FOLIO_CLOUD_CONFIG = {url: 'https://YOUR_PROJECT.supabase.co', publishableKey: 'sb_publishable_...'};
8. อัปโหลด index.html ทับไฟล์เดิมใน GitHub แล้ว Commit changes รอ Vercel Deploy เสร็จ
9. ทดสอบล็อกอินด้วยอีเมลเดียวกันบนคอมและ iPad จดโน้ตสั้น ๆ แล้วกลับหน้าบัญชี กดซิงก์ตอนนี้

การใช้งาน
- ข้อมูลก่อนล็อกอินยังอยู่ในเครื่องเดิม กด “เพิ่มข้อมูลเดิมเข้าบัญชี” เมื่อต้องการย้ายเข้าบัญชี
- บันทึกในเครื่องก่อนแล้วซิงก์อัตโนมัติ ตรวจข้อมูลออนไลน์ทุก 30 วินาทีและเมื่อกลับมาเปิดเว็บ
- ขณะเปิดโน้ตหรือแบบฟอร์มจะไม่แทนที่หน้าที่กำลังแก้ไข กลับหน้าบัญชีแล้วกดซิงก์
- หากสองเครื่องแก้ไขพร้อมกัน ต้องเลือกเวอร์ชัน ข้อมูลในเครื่องจะถูกดาวน์โหลดสำรองก่อนเลือก
- ยังไม่มีการรวมการแก้ไขพร้อมกันอัตโนมัติ
- ซิงก์ทั้งพื้นที่เรียนรวมลายมือ จำกัดข้อมูลออนไลน์ไม่เกินประมาณ 20 MB ต่อบัญชีในรุ่นนี้
- ออกจากระบบแล้วยังมีสำเนาบัญชีในเบราว์เซอร์เดิม เมื่อใช้เครื่องสาธารณะควรล้างข้อมูลเว็บไซต์หลังใช้งาน
- การซิงก์ข้ามสองโดเมนต้องตั้งค่า Supabase โปรเจกต์เดียวกันทั้งสองเว็บ

การตรวจสอบ
ผ่านการทดสอบโค้ดด้วยระบบจำลอง: แยกบัญชี, เก็บข้อมูลเดิม, ออฟไลน์, ความขัดแย้งของเวอร์ชัน, ข้อมูลเปลี่ยนระหว่างอัปโหลด
ยังไม่ได้ตรวจบนมือถือจริง หรือทดสอบลิงก์อีเมล และซิงก์ผ่านบัญชีจริง การอ่านข้อมูลโดยไม่ล็อกอินถูกปฏิเสธตามที่ตั้งค่าไว้
